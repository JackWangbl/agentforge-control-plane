# AgentForge 控制平面 · 项目说明

AgentForge Control Plane 是一套本机可跑的 **Agent 管理控制面**：用 FastAPI 提供 API，同源托管管理台页面，数据落在 MySQL（开发测试可用 SQLite）。打开 [http://127.0.0.1:8080](http://127.0.0.1:8080) 即可使用。

它要解决的问题不是「再写一个聊天机器人」，而是把企业里用 Agent 时会碰到的几件事收拢到一个界面里：

- 谁能看、谁能改（租户 + 角色）
- Agent 用哪套模型、哪些技能、哪些工具、哪条沙箱策略
- 对话有没有留下来、链路能不能复盘
- 用数据集持续测质量，而不是靠感觉

默认账号：`linmo / admin123`（平台管理员），另有 `developer / dev123`、`auditor / audit123`、`demo / demo123`。

## 系统怎么分层

```text
浏览器管理台（static/）
        │  REST
FastAPI 控制面（app/main.py + routers）
        │
        ├── 访问控制：登录、租户、RBAC（app/access/）
        ├── 注册表：Agent / MCP / Skill / 模型 / 编排 / 沙箱
        ├── 运行时：调试台会话、工具执行、沙箱、评测工人
        └── 观测：本机 Trace、AgentScope Studio、可选 Langfuse
                │
              MySQL
```

和 AgentScope 的对接集中在 `app/services/agentscope_adapter.py`：启动时尝试 `agentscope.init`，MCP 客户端按官方类型构造；真正聊天目前走 OpenAI 兼容的 `/chat/completions`，这样没装 AgentScope 也能先把控制面跑起来。更细的对照见同目录的《agentscope实战》。

## 运行中心

### 运行概览

登录后的首页。按当前租户汇总会话量、成功率、平均延迟、Token，并列出 Agent 健康度和最近几条真实会话。

数字里有一部分是展示放大（例如请求数会乘一个系数），**会话列表本身是库里的真实记录**。要看准业务数据，以「会话查询」和调试台为准。

### 会话查询

检索所有已经落库的对话：Session ID、用户、Agent、状态、消息条数、耗时。支持按 Agent、状态、关键字过滤，点「查看」能打开完整消息和关联 Trace。

会话来自 Agent 调试台和数据测试跑出来的调用，不是演示假数据（启动时会清掉早期内置的展示会话）。

### AgentScope Studio

控制面把一次调试或评测的 spans、Token、耗时推到本机 AgentScope Studio（默认 `http://127.0.0.1:3000`）。页面上用来看「这次 Agent 到底走了哪些步骤」。

Studio 没开着也不影响控制面本身：对话照常跑，只是外部轨迹页连不上。环境变量 `AGENTSCOPE_STUDIO_URL` 可改地址。

### 数据测试

用标准数据集回归 Agent 质量，不再只靠手工点几句。

| 子页 | 做什么 |
| --- | --- |
| 数据集 | 新建集合，手动加用例，或导入 CSV / JSON / JSONL |
| 测试任务 | 选择 Agent、数据集、打分方式，发起在线抽检或离线回归 |
| 报告 | 看通过率、失败原因、实际输出，可导出 CSV、按同样配置重跑 |

打分方式：

- **包含匹配 / 完全匹配 / 正则**：规则判分，适合标准答案比较稳定的题
- **LLM 判分**：另选裁判模型，适合开放式回答

空数据集不能开测。在线抽检同步跑（最多 10 条）；离线任务进队列，由后台 `eval-worker` 领取执行。每条用例都会走和调试台同一套 `generate_chat_reply`，因此 Skill、MCP、沙箱绑定在评测里同样生效。

### Agent 调试台

给单个 Agent 做对话试验。每个 Agent 有独立工作目录（`workspaces/`），会话、链路、最近配置会写进去。

一次发送大致会：

1. 拼系统提示（人设 + 已绑 Skill 正文）
2. 把已绑 MCP / 浏览器 / 沙箱工具交给模型
3. 模型若要调工具，控制面执行后再回灌，最多多轮
4. 没有模型密钥时走预览回复，不会假称「已真实调用」
5. 结果写入会话、Trace，并尝试导出到 Studio

这是日常验证「这个 Agent 现在到底会不会干活」的入口。

## 构建中心

### Agent 管理

登记一个可发布的 Agent：名称、职责、系统提示、所用模型、版本、发布状态。

还能绑定三样东西，运行时才会生效：

- **技能**：把 SKILL.md 说明注入提示词
- **MCP 工具**：模型可调用的函数列表
- **执行沙箱**：按策略隔离地跑 Python / Shell

不同 Agent 可以绑不同沙箱，也可以不绑。没绑沙箱的 Agent 调 `sandbox_run_python` 会被拒绝。

### MCP 工具

集中登记工具服务，支持：

- **HTTP Stream**（Streamable HTTP，推荐接远程 MCP）
- **SSE**
- **StdIO**（本地进程）
- 内置「本地工具」「浏览器工具」：时间、计算、知识检索、列 Agent、打开网页等

保存后可以探测连通性、发现工具列表。Agent 编辑页勾选后，调试台和评测才会允许调用对应工具名。

### Skill 管理

人工维护可复用的专业说明，对应仓库里的 `skills/*/SKILL.md`。控制面可以预览指令、编辑后写回文件。

Skill **不是**可执行代码，而是给模型看的规程。例如客服口径、会议纪要结构。Agent 绑上之后，这些文字会出现在系统提示里。

## 平台设置

### 模型配置

填写供应商、模型 ID、兼容接口地址、温度，以及 API 密钥（或环境变量名如 `DASHSCOPE_API_KEY`）。

密钥在接口里会脱敏。没有可用密钥时，调试台仍能聊，但只给预览回复。DashScope / OpenAI / 本地兼容网关都可以配；DeepSeek 的旧模型名会在适配层归一到当前可用 ID。

### 沙箱管理

定义代码执行策略：运行时镜像或本机 Python 版本、CPU / 内存、超时、网络（拒绝 / 白名单 / 允许）。

卡片上的「试跑代码」会真执行 `print('sandbox-ok', 1+1)`，断网策略下会验证 Python 联网被拦住。

执行后端：

1. runtime 写成 Docker / AgentScope 官方镜像，并且本机装了 `agentscope-runtime` 时，走官方沙箱
2. 否则走本机隔离：`python -I` 或 `/bin/sh`，超时、可选内存上限、注入 socket 阻断

工作目录按策略分开：`workspaces/_sandboxes/{id}-{name}`。要让两个 Agent 文件也不互相看见，各建一条策略再分别绑定。

### 权限管理

按 AgentScope 思路做隔离：**默认属主可见，同租户按角色共享，跨租户不可见**。

可管理：

- **租户**：默认租户、演示租户
- **角色**：权限点列表（`agent:read`、`eval:run`、`*` 等）
- **用户**：账号、角色、启用状态

平台管理员能进所有模块；开发者可建 Agent、跑评测；审计员默认只能看会话和链路。侧栏会按权限隐藏入口。

## 一次完整使用路径

1. 用管理员登录，在「模型配置」里填好密钥。
2. 在「Skill / MCP / 沙箱」里准备能力，再到「Agent 管理」里绑到目标 Agent。
3. 打开「调试台」对话，确认工具和沙箱真的被调用。
4. 在「数据测试」里建数据集、加用例，创建测试看报告。
5. 需要复盘步骤时，开 AgentScope Studio，对照控制面里的链路。

本地启动：

```bash
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8080 --reload
```

接口文档在 `/docs`。自动化测试用 SQLite，不依赖你的 MySQL。
